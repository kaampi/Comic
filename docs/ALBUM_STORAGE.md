# Local album storage and Codex preparation

Comic keeps its catalog, album revisions and binary assets in local IndexedDB in both the web and desktop apps. The catalog loads album metadata and covers. Comic opens the full album when the user selects it. The editor keeps its existing image representation in memory. Local writes encode the changed album, reuse image hashes, and commit the new revision and catalog together. Each new local revision has a UUID. A catalog revision check prevents a stale tab from replacing another tab's saved changes.

The legacy IndexedDB collection and localStorage source stay available for recovery. Migration stages one album at a time and resumes from the last committed stage when the legacy source matches. It verifies the album contents and the hashes of referenced binaries before publishing the catalog. A changed source, invalid catalog, quota failure or missing media stops the operation. Comic exposes the retained sources and up to three new local checkpoints in Local recovery. Existing portable album backups remain format 1. The error screen and local save error action can export a copy of the active in-memory album.

Autosave waits 200 ms after the last edit and starts within one second during a continuous burst. A hidden window also flushes pending work. The local status reflects the IndexedDB commit. The separate backup action still creates a user-controlled portable file. Local checkpoint history is limited to three entries. The database currently retains unreferenced album revisions and binary blobs, including assets from deleted albums. A later retention pass needs to prove reachability from active manifests, staged migrations and retained recovery points before removing data.

The [Codex creative assets roadmap](https://github.com/kaampi/Codex/blob/docs/shared-creative-assets-plan/docs/shared-creative-assets-plan.md) and [workspace ownership contract](https://github.com/kaampi/Write/blob/main/docs/core-architecture.md) inform the draft types in `src/creativeAssetContract.ts`. They are compile-time proposals. Existing album IDs and imported provenance stay as they are. A future adapter must map scoped legacy IDs explicitly, pin source revisions and verify the requesting app and its grants at the server. A grant permits reading published assets. Writes require ownership, and changes to Write canon require Write's review flow. Consumer copies remain independent, including after a grant is revoked. The workspace scope, versioned validators and transport are pending agreement.

Anatomy, appearance and outfits can evolve independently. A reusable outfit lists anatomical requirements. A Character Look combines pinned revisions and can carry a separate dressed reference sheet. Complete private snapshots require a versioned album manifest, image history, all referenced bytes and pinned provenance. A future adapter must verify these dependencies before acknowledging the snapshot and support offline restoration after the original source is removed. Private snapshot workspaces are owner-only. Local save, external backup and any future Codex acknowledgment are separate states. Comic has no Codex connection or automatic publication.
